Kanlane con Claude

Conecta Claude a tus tareas con el servidor MCP de Kanlane

Dale a tu asistente un token de un proyecto y podrá ver sus tareas, pasarlas a «En curso» o a «Hecho», dejar una nota con lo que ha hecho y crear tareas nuevas. Tú decides qué proyecto, si solo lee, y cuándo se acaba.

En resumen

Kanlane tiene un servidor MCP (Model Context Protocol): una dirección a la que se conecta un asistente de IA, como Claude Code, para trabajar con las tareas de un proyecto. Funciona con un token que creas en Ajustes, vale para un solo proyecto, puede ser de solo lectura y se revoca cuando quieras. Kanlane no incluye un asistente propio ni llama a ningún modelo: tú conectas el tuyo. No sirve para proyectos cifrados, y el asistente no ve tus fichas de clientes, tus reuniones ni tus contraseñas.

Qué puede hacer el asistente

Cinco herramientas, todas sobre las tareas del proyecto del token. Trabajan con las columnas reales de tu tablero, se llamen como se llamen.

Listar tareas

Las columnas del proyecto y sus tareas. Por defecto, las que no están en una columna de hechas; también por columna.

Leer una tarea

Descripción, subtareas, fecha, etiquetas y sus últimas notas y líneas de actividad.

Mover de columna

De pendiente a en curso, o a una columna de hechas para completarla. La tarea queda al final de la columna.

Añadir una nota

Para dejar dicho qué se hizo o qué falta. En texto o Markdown.

Crear una tarea

Con título, descripción, columna, fecha límite y etiquetas.

Tareas que se repiten

Al completar una, se crea la siguiente, igual que cuando la completas tú.

Así queda en la tarea

Un ejemplo con datos inventados. Lo que hace un asistente se distingue de lo que haces tú: queda firmado con el nombre de quien creó el token y el del token.

Cómo conectarlo

  1. Abre el proyecto y ve a Ajustes → Integraciones. El apartado se llama «Asistentes de IA (MCP)». Hace falta una cuenta: no está en el modo invitado.
  2. Crea un token. Ponle un nombre que reconozcas y marca «Solo lectura» si no quieres que cambie nada.
  3. Copia el comando y pégalo en un terminal. El token se enseña una sola vez. Kanlane no lo guarda: solo conserva su huella para reconocerlo.
  4. Pídeselo a tu asistente. Por ejemplo: «lista las tareas pendientes de Kanlane», «pasa esta a En curso» o «márcala como hecha y deja una nota con lo que has cambiado».

El comando para Claude Code

Kanlane te lo da ya escrito con tu token. Tiene esta forma:

claude mcp add --transport http kanlane https://kanlane.com/__/mcp/v1 --header "Authorization: Bearer kl_…"

Otros clientes MCP se conectan a la misma dirección, https://kanlane.com/__/mcp/v1, por HTTP y con el token en la cabecera Authorization.

Permisos y seguridad

Lo que controlas

  • Cada token vale para un solo proyecto. Ni siquiera sirve para otro proyecto de tu misma cuenta.
  • Puede ser de solo lectura: entonces el asistente ni siquiera ve las herramientas que escriben.
  • Lo revocas desde Ajustes y deja de funcionar en la siguiente llamada.
  • En un equipo, el token puede lo mismo que tú en ese momento: si pasas a lector, deja de escribir; si sales del equipo, deja de valer.
  • Cada cambio queda anotado en la actividad de la tarea, con tu nombre y el del token.

Lo que conviene saber

  • Lo que el asistente lee sale de Kanlane hacia el servicio de tu asistente, con sus propias condiciones de privacidad.
  • Quien tenga el token puede usarlo: trátalo como una contraseña.
  • Una tarea puede llevar texto escrito por otra persona o llegado por correo. Kanlane se lo entrega al asistente marcado como datos, no como instrucciones, pero eres tú quien decide qué le dejas hacer.
  • Las reglas de automatización «al crear» y «al mover» no se disparan con lo que hace el asistente.
  • Hay límites: 60 llamadas por minuto por token y 2 000 cambios al día por proyecto.

Esto no es para ti si…

  • Tu proyecto está cifrado, con «Cifrado total» o «Gestionado por Kanlane»: el servidor no tiene su clave y no puede leer sus tareas.
  • Esperas un asistente dentro de Kanlane: no lo hay. Kanlane no llama a ningún modelo; solo abre la puerta al tuyo.
  • Quieres que el asistente consulte las fichas de tus clientes, el calendario o las contraseñas: solo trabaja con tareas.
  • Necesitas que edite el título o la descripción de una tarea que ya existe, o que la borre: no hay herramienta para eso.
  • Quieres que tus automatizaciones se ejecuten cuando el asistente mueve o crea una tarea.
  • Usas Kanlane como invitado o en modo local: sin cuenta no hay tokens.
  • Solo usas el conector de claude.ai en la web: no está probado y puede pedir un tipo de acceso que Kanlane aún no ofrece.

Preguntas frecuentes

¿Qué es el servidor MCP de Kanlane?

Es una dirección de Kanlane a la que se conecta un asistente de IA compatible con el protocolo MCP (Model Context Protocol), como Claude Code. Con un token de tu proyecto, el asistente puede leer sus tareas, moverlas de columna, añadirles notas y crear tareas nuevas.

¿Qué puede ver y cambiar el asistente?

Solo las tareas del proyecto para el que creaste el token: título, descripción, columna, fechas, etiquetas, subtareas, notas y el nombre del cliente y del contacto asignados a cada tarea. No ve las fichas de clientes y contactos, las reuniones ni las contraseñas, y no puede borrar tareas, cambiar las columnas ni tocar los permisos del proyecto.

¿Puedo dar acceso de solo lectura?

Sí. Al crear el token marcas «Solo lectura» y el asistente puede listar y leer tareas, pero no moverlas, anotarlas ni crearlas. Si en un equipo solo puedes leer el proyecto, tus tokens son siempre de solo lectura.

¿Funciona con proyectos cifrados?

No. En un proyecto con «Cifrado total» o «Gestionado por Kanlane» el servidor no tiene la clave del proyecto, así que no puede leer ni escribir sus tareas. Si un proyecto pasa a estar cifrado, sus tokens se retiran.

¿Se disparan mis automatizaciones cuando el asistente mueve una tarea?

No. Las reglas «al crear» y «al mover» las ejecuta el navegador de quien cambia la tarea, y aquí el cambio lo hace el servidor. La única excepción es una tarea que se repite: al completarla se crea la siguiente.

¿Con qué asistentes funciona?

Con clientes MCP que se conectan por HTTP y envían el token en la cabecera Authorization. Está probado con el cliente oficial del protocolo, y el comando de esta página es el de Claude Code. El conector de claude.ai en la web no está probado y puede exigir un tipo de acceso (OAuth) que Kanlane todavía no ofrece.

¿Qué hago si pierdo un token o ya no lo necesito?

Revócalo en Ajustes → Integraciones. Deja de funcionar en la siguiente llamada y no se puede recuperar; si hace falta, creas otro. Al borrar un proyecto se retiran sus tokens, y al eliminar tu cuenta, todos los que creaste.

¿Tiene coste o límites?

No tiene coste adicional. Cada token admite 60 llamadas por minuto y cada proyecto, 2 000 cambios al día entre todos sus tokens; leer no cuenta para ese tope. Un proyecto puede tener hasta 10 tokens.

Pruébalo en un proyecto

Crea tu cuenta, abre un proyecto sin cifrado y ve a Ajustes → Integraciones para crear el primer token. La demo enseña el tablero con datos de ejemplo, pero no tiene servidor MCP: hace falta una cuenta.
